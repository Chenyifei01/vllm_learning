# 独立文档交付与 HTML/PDF 导出

仅在需要单文件交付或导出这些格式时读取。用户指定的格式、目录、模板及现有可用 PDF/演示文稿技能优先；不为了导出擅自安装插件或更改报告内容。

## 交付边界

- 先确认事实源和交付范围：独立报告还是连同附件的仓库文档；Markdown、HTML、PDF、PPTX 中哪些是必需成品。已有 Markdown 报告通常作为统一正文来源。
- 本仓库按“一个项目一个文件夹”组织成品。除用户另定位置外，同一算子的 HTML/PDF/PPTX 与 Markdown 放在该项目目录，不写入仓库级 `output/html`、`output/pdf` 等汇总目录。导出工具要求单独输出目录时，先在临时位置生成并验收，再把最终文件放回项目目录。
- 单文件成品需脱离图片目录和私仓独立阅读。必要的环境、口径和机制保留在正文；不要重新添加已删除的附录、姊妹报告引用或不可访问的代码定位表。
- 导出前记录源文件状态。导出期间源文件被用户更新时，基于新版本重导并复查，不交付旧正文与新图表混合的结果。
- 临时脚本、页面截图和校验日志不是默认成品。只清理本任务生成、路径已确认且没有其他工作使用的临时文件；保留用户文件与正式输出。

## 自包含 HTML

1. 用可用的 Markdown 解析器生成正文，不用正则替代完整解析。保留表格、代码、强调、标题层级和数学符号；目录锚点唯一。
2. 以源 Markdown 所在目录解析相对图片路径。确认图片存在；编码中文路径时避免把已有转义重复转义，不将引用意外解析到无关文件。
3. 将 SVG/PNG 等图片嵌入 HTML，样式内嵌。SVG 可以用 `data:image/svg+xml;base64,...` 的 `<img>`，避免多个 SVG 的样式/ID 串扰；只有目标查看器实际验证支持时才选择其他内联方式。
4. 资源内嵌不等于自动安全或离线可用。检查 SVG 外链、脚本、事件属性、`foreignObject` 与外部 CSS 依赖，不把未经审查的动态内容直接注入页面。使用页面加载与网络请求检查，确认渲染所需资源没有外部依赖。
5. 等字体就绪、所有图片加载/解码完成后再截图或打印。检查图片数量、自然尺寸、表格/代码溢出以及链接与图注，实际查看图表，不能只验证 XML 能解析。
6. 正文字体以本地可用中文字体和回退列表为主，不依赖远程字体。需要跨设备完全固定版式时交付字体已嵌入的 PDF，不宣称 HTML 在所有设备上字体完全一致。

仓库内 Markdown 可继续引用相对路径；这种 Markdown 本身不是单文件图文成品。内联 SVG、HTML 或 data URI 是否能在目标 Markdown 平台显示，要用该查看器验证，不能根据浏览器渲染 HTML 的结果推断。

## PDF 生成与排版

- 先检查本机可用运行时、库、浏览器/渲染器和中文字体。不要硬编码开发者用户名、缓存版本或浏览器安装路径到通用技能，也不要假定 Codex 和 Claude Code 配备相同工具。
- 现有报告可从确认过的 HTML 以打印样式生成 PDF；重视矢量图、代码和中文时先做小样验证。可用 Markdown 解析器加无头浏览器只是可选路径，不是必须安装的依赖。
- 浏览器导出使用独立临时上下文，不接管个人浏览器会话；等待资源就绪后设置明确的纸张、边距、页码和打印配色。只在工具支持时启用目录书签与带标签 PDF。
- 使用单独的打印样式调整字号、表格列宽和代码换行，不靠压缩全页截图来生成不可搜索的正文。保留图形比例；优先让 SVG 保持矢量，转换后检查清晰度。
- 标题、引导句与其后表格/代码避免孤立跨页；能在一页内放下的表格优先整表保留。大表允许分页并重复表头，不能为保持整表裁掉内容或挤成不可读的小字。
- HTML 屏幕版无溢出不代表纸张版无溢出。按打印内容宽度复查表格、长符号串、代码和图片；不要求固定页数，除非用户指定。

## 导出后验收

1. 确认文件非空、可重新打开，页数/标题/章节/图片数量符合源文档；HTML 离线加载所有图表。
2. 用可用工具渲染并查看 PDF 每一页或演示稿每一页，检查中文缺字、图例/标签、裁切、重叠、孤立标题及不合理分页。修复后重渲染并复查最终版本，旧版本截图不能证明新文件合格。
3. 提取 PDF 正文，确认非空、无替代字符，重要段落、表格值和代码均完整。可按短文本片段与 HTML 正文比对；先排除页眉、页脚、页码与空白导致的跨页差异。图内文字的提取失败不能单独证明图有缺陷，需视觉核验。
4. 核验中文与其他实际使用的字体是否嵌入，避免依赖读者本机字体。提取工具控制台出现乱码时先区分输出编码问题与 PDF 本身缺字；不能仅凭控制台显示判断文档损坏。
5. 对 PPTX，资源打包与可编辑性需要另行检查，渲染截图不能证明对象可编辑。演示稿导出的 PDF 应与幻灯片顺序和页面比例一致。
6. 无法渲染、提取或检查嵌入字体时，明确说明已完成项与未验证项，不声称完成视觉/完整性验收。

## 提交与推送

只有本次任务获得用户授权时执行提交/推送；“完善 skills”本身不自动授权发布。

- 先检查工作区和暂存区，区分用户已有变更与本任务成品。显式列出并暂存目标文件，避免 `git add .` 带入其他报告、skills 或临时文件。
- 检查暂存文件名、内容差异和空白问题，再提交。若技能入口依赖共享指南，提交时一起包含必需指南，不能留下断链入口。
- 推送到已确认的分支，不强制覆盖。失败时先确定原因；需要新增权限或有冲突无法安全解决时停止并说明。
- 不输出带凭据的 remote URL；远端输出和错误也需遮蔽凭据。推送后比对目标远端分支的 commit 与本地 HEAD，而不是仅凭“命令运行结束”判定成功。
- 交付时列出成品位置、版本/提交（若已发布）、验收情况及必要限制。没有推送就明确说本地已更新，不冒称远端同步。
