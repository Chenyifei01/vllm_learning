# Ascend 算子优化 PPT 写作指南

## 先确定讲述任务

查看用户给的报告、代码、数据、PPT 模板和演讲时长。沿用现有模板、公司品牌、页数和语言要求。若没有模板，不要把整篇报告逐页缩小贴进幻灯片；先选定听众需要理解或决定的核心问题，再把证据整理成清晰的讲述顺序。

推荐故事线（按项目裁剪，不固定页数）：

1. 算子在模型/系统中的位置和优化目标。
2. 生产 workload、硬件与 baseline。
3. 如何确认实际命中的路径和主要瓶颈。
4. 优化设计：数据流/执行序列的前后对比。
5. 按收益和风险讲关键优化轮次。
6. 正确性、边界和负结果。
7. 最终性能与剩余瓶颈。
8. 可复用结论、适用范围和读者可访问的复现入口（若需要）。

短讲保留主路径证据和最终结果；长讲可加入内核细节、profiler 归因和失败实验。内容多时移入讲稿备注，附录仅在用户需要时添加，正文页只保留支撑当页结论所需的证据。独立演示稿不依赖另一个报告或私仓才能理解机制；不要恢复源报告中按用户要求删掉的无关背景、附录和私仓定位表。

## 页面信息设计

- 一页讲一个主要事实、机制或结论。标题写明页主题；关键结果页可用有数据支撑的结论标题。
- 让流程页解释数据如何流动，让对比页展示改动前后，让结果页给出一致口径的数值。
- 每页保持清楚的视觉层级：标题、主要图/表、必要注释和来源。删掉不能帮助听众理解的装饰、口号和重复文字。
- 正文优先短句和精简标签。术语首次出现时解释；不要把报告段落直接粘贴成密集 bullet。
- 沿用用户提供的配色、字体和母版。没有模板时保持全稿的字号、颜色、图例与单位一致，并在投影视距下可读。
- 不靠缩小字体塞入更多文字；先删减、拆页或把细节放备注/附录。

## 技术图表

- benchmark 图注明 dtype、shape/tokens、硬件、计时口径和对照版本。数字与报告保持一致，百分比要能从表格复算。
- 能用原生可编辑图表、表格或形状表达时，保持对象可编辑。性能趋势用图，精确矩阵数据用表，数据流和同步关系用简单流程图/泳道图。
- 流水图使用共同时间方向和清晰资源泳道，标出装载、计算、落盘、等待、双缓冲槽位和关键重叠，不要用示意图冒充真实 trace。
- 画双缓冲时表达“同槽位上一轮消费完成 → 下一轮装载”的依赖；示意时长需标明估算或示意，不伪装成从 trace 测得。
- 归因图区分测量值、计算值与假设值。用颜色之外的标签/线型标识系列，使用一致单位。
- 如果图来自外部截图，确保字清晰且裁切完整；如果重新绘制图表，记录数据源并保留可编辑性。
- 不为“视觉丰富”添加无证据图片、伪 3D、装饰性渐变或重复图例。

## 技术叙事约束

- 把测量数据、静态推导、假设和结论分别标清；不能将一个 shape 的收益表述成全场景提升。
- 说明性能计数器之间可能存在重叠。pipe busy 百分比不是可直接相加的时间分解。
- 对应报告里的分母、采集点和基线逐项对齐；活跃时间百分比与墙钟占比不能混用，逐轮收益不直接累加为总收益。
- 主动展示正确性验证、噪声范围、失败尝试和回退成本。不要把未验证的方案写成已交付能力。
- 正确性页按用户要求简述为“精度测试通过”，可补覆盖和限制，但须先核实当前版本的测试记录；不默认加入详细断言或私仓测试文件路径。
- 带宽、理论下限和加速比写出单位和比较基线。极小延迟档同时展示绝对差。
- 把详细代码留给真正需要的页面；代码截图要足够大、裁掉无关部分，并标出变化行。私仓文件路径、分支和 commit 仅在用户需要且读者可访问时出现；机制说明可直接使用必要的伪代码或函数名。
- 区分 decode/prefill 或不同变体，当量级或瓶颈差异让共用坐标难以阅读时拆开展示。

## 生成与交付检查

按运行环境选择可用的演示文稿工具或库，不假定 Codex 和 Claude Code 安装了同一套插件。先检查模板及工具能力；保留用户要求的可编辑对象。最终交付 PPTX，除非用户指定其他格式。

只上传单文件时，确认图片和图表资源打包进 PPTX，不依赖本地绝对路径或链接媒体。若另交 PDF/HTML，读取 [document-export.md](document-export.md) 的相应检查；PDF 不替代用户要求的可编辑 PPTX，不把报告的分页 PDF 冒充演示稿 PDF。

导出后检查完整演示文稿，而不只检查源代码或第一页：

- 页数和顺序符合约定；
- 每页渲染完整，无文字裁切、重叠、错位或字体替换导致的溢出；
- 图表、轴标题、图例、数据标签和脚注易读且与源数据相符；
- 母版、颜色、字体、页码、页脚保持一致；
- 备注/引用在需要时存在，外部事实可追溯；
- 所有媒体已打包；讲稿备注也没有泄露用户要求移除的内部背景或私仓定位；
- 如发现问题，修复后重渲染受影响页面并复查。

如果环境无法渲染 PPTX，要明确说明哪些检查完成、哪些无法验证，不声称已视觉验收。
